# Phase 2 Technical README: Graph Construction, Traceability, and Styling

This document explains how Phase 2 is implemented in the current pipeline.

## Scope of Phase 2

Phase 2 covers:
- Semantic graph construction from predicted keywords
- Node and edge traceability to requirements IDs
- Edge shared-requirement metadata
- Node visual highlighting by relation count
- GEXF export

Main modules:
- `src/run_pipeline.py`
- `src/graph/build_graph.py`
- `src/keywords/normalize.py`

## Phase 2 Input Contract

Input to Phase 2 is generated by Phase 1:
- One normalized keyword list per requirement row
- One requirement identifier (`source_id`) per row

Requirements used for graph/inference always come from:
- `data/crowd.csv`

`tags` are not used to build the graph structure.

## Graph Construction Strategy

Graph type:
- Undirected `networkx.Graph`

Node definition:
- One node per unique normalized keyword

Edge definition:
- Semantic similarity between keyword embeddings
- Similarity model: `SentenceTransformer` (default `all-MiniLM-L6-v2`)
- Edge created only if cosine similarity is at least `--semantic-threshold`

Edge attributes created at build stage:
- `weight`: cosine similarity
- `semantic_similarity`: cosine similarity (explicit alias)

## Requirement Traceability on Nodes

After base graph construction, each keyword node is annotated with requirement provenance.

Node attributes:
- `requirement_ids`: comma-separated requirement IDs where the keyword appears
- `requirement_count`: number of linked requirements

This enables direct traceability from keyword to one or many source requirements.

## Shared Requirement Metadata on Edges

Each edge stores requirement overlap between its two endpoint keywords.

Edge attributes:
- `shared_requirement_ids`: comma-separated intersection of requirement IDs
- `shared_requirement_count`: size of that intersection

This allows identifying whether two related keywords co-occur in the same requirements and in how many.

## Visual Highlighting by Degree

Nodes are automatically color-coded by relation count (node degree):

- Degree `0`: red (`#e53935`)
- Degree `1-3`: orange (`#fb8c00`)
- Degree `4-5`: yellow (`#fdd835`)
- Degree `>5`: green (`#43a047`)

Node attributes added for styling and filtering:
- `relation_count`
- `relation_color`
- `relation_bucket`
- `viz.color` (GEXF-compatible RGBA block)

## Export Format

Final graph is exported as GEXF to:
- `--graph-out` (default `results/keyword_graph.gexf`)

The GEXF includes:
- Semantic structure (nodes and edges)
- Node requirement provenance
- Edge shared-requirement metadata
- Degree-based visual style attributes

## Processing Order in Phase 2

1. Parse normalized keywords for each prediction
2. Build semantic similarity graph from all unique keywords
3. Attach node requirement references
4. Attach edge shared requirement references
5. Apply degree-based node styling
6. Save GEXF


## Outputs Produced by Phase 2

- Fully annotated and styled GEXF graph:
  - `results/keyword_graph.gexf` (or custom output path)
