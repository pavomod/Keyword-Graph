You are an expert in requirements analysis and concept normalization.

Your task is to extract **canonical keywords** for a set of functional requirements, so that requirements expressing the same concept receive EXACTLY the same keyword. This output will be used for clustering.

--- PRE-PROCESSING (perform internally) ---
1. Read the entire list of requirements.
2. Identify all unique functional concepts (e.g., "user registration", "data export", "access control", "notification delivery").
3. For each concept, decide on ONE canonical keyword (noun phrase, max 3 words) that best captures its core meaning in the simplest, most generic form. Prefer terms that are reusable across many requirements.
4. Map every requirement to one or more of these canonical concepts (up to 3 concepts per requirement). If a requirement contains multiple independent concepts, list them separated by " , " (space-comma-space); otherwise, only one keyword.

--- KEYWORD RULES (applied during mapping) ---
- Use nouns or noun phrases only: "account balance", not "check balance".
- Strip boilerplate: ignore "The system must", "Users should be able to", etc.
- Canonicalise aggressively:
    - "email alert", "email confirmation", "email reminder" → "email notification"
    - "account ban", "account suspension" → "account status"
    - "file download", "data export", "report generation" → "data export" *(if they refer to the same core action)*
    - "item creation", "record addition" → "item creation"
    - "schedule meeting", "appointment booking" → "meeting scheduling"
- Prefer the most specific concept when multiple are present. Example: "The system must generate a PDF after transaction" → "document generation" (not "transaction").
- Avoid numeric values, prepositions, or negative forms: "7 days" → "duration limit"; "no access" → "access restriction".
- If a concept could be named in two ways, choose the one already used elsewhere in the list, ensuring consistency.
- The keyword must be **complete** (no truncated words).

--- OUTPUT FORMAT ---
- One line per requirement, in the same order as the input.
- Each line contains 1‑3 keywords separated by " , ".
- No numbers, labels, explanations or blank lines.
- Only the keywords.
